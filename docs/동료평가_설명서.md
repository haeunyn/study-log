## 1-③ 리다이렉트가 적용되어 새로고침해도 중복 요청이 발생하지 않는가 ★ **이 미션의 핵심**

**보여줄 방법 — 등록 직후 F5를 3~4번 연타하세요**

**확인 포인트** — 주소창이 `/logs/8`로 바뀌어 있고, 목록으로 가면 **1건만** 늘었음

> 💡 **말보다 이게 강력합니다.** F5를 여러 번 누르고 목록 건수를 보여주세요.

**읽을 말**

> "**PRG(Post-Redirect-Get) 패턴**입니다.
>
> POST를 처리한 뒤 화면을 바로 그리면, **그 화면의 주소는 여전히 POST 주소**입니다.
> 사용자가 F5를 누르면 브라우저가 '양식을 다시 제출할까요?'를 묻고,
> 확인하면 **같은 글이 또 등록됩니다.**
>
> PRG는 POST 처리 후 **리다이렉트를 돌려줘서** 주소창이 GET 주소로 바뀌게 합니다.
> 그 뒤 새로고침은 **GET이 다시 갈 뿐이라 안전합니다.**"

### ★ 왜 303인가 — **이걸 정확히 말하면 확실히 통과합니다**

> "**302 Found**는 재요청 시 **원래 메서드를 유지해도 된다**는 해석의 여지가 있어서,
> 일부 클라이언트는 **POST로 다시 보냅니다.** 그러면 PRG의 목적이 깨집니다.
>
> **303 See Other**는 규격상 **반드시 GET으로 바꿔서** 요청하라는 뜻입니다.
> 반대로 **307/308은 메서드를 유지**하라는 뜻이라 여기서는 쓰면 안 됩니다."

| 코드 | 의미 | PRG에 적합? |
|---|---|---|
| 301/302 | 이동됨 (메서드 유지 여부가 **모호**) | ❌ |
| **303** | **다른 자원을 GET으로 보라** | ✅ |
| 307/308 | 이동됨, **메서드 유지** | ❌ (POST가 반복됨) |

### ★ 함께 말하면 좋은 것: 삭제는 왜 링크가 아닌가

> "삭제를 GET 링크로 만들면, **브라우저의 미리 읽기나 검색엔진 크롤러가
> 링크를 훑는 것만으로 데이터가 지워집니다.**
> 그래서 제 코드에서 삭제는 링크가 아니라 **`<form method="post">`의 버튼**입니다.
> `templates/detail.html`에 있습니다."

## 1-④ SQLite DB 파일이 생성되어 있고, 직접 확인할 수 있는가

**보여줄 방법 — 터미널에서**
```bash
ls -l database.db
python -c "
import sqlite3
con = sqlite3.connect('database.db')
for row in con.execute('SELECT id, title, studied_on, minutes, category FROM study_logs'):
    print(row)
"
```

**확인 포인트** — 화면에서 본 내용이 DB에도 있음

**읽을 말**

> "DB 파일은 **프로젝트 폴더 안에** 만들어집니다. `database.py`에서
> `Path(__file__).resolve().parent`로 **이 파일이 있는 폴더**를 기준으로 경로를 잡았습니다.
>
> 상대 경로(`sqlite:///database.db`)로 두면 **어느 폴더에서 서버를 실행했는지에 따라
> DB 파일이 다른 곳에 생깁니다.** 그러면 '데이터가 사라졌다'고 착각하게 됩니다.
> 절대 경로로 고정한 이유입니다.
>
> 그리고 `connect_args={'check_same_thread': False}`를 줬습니다.
> **SQLite는 기본적으로 '연결을 만든 스레드에서만 써라'고 막습니다.**
> FastAPI는 여러 스레드에서 요청을 처리하니 이 제한을 풀어야 합니다.
> 대신 **세션을 요청마다 따로 만들기 때문에** 충돌하지 않습니다."

### 💡 SQL을 직접 보여주고 싶다면

> "`database.py`의 `echo=False`를 **`True`로 바꾸면** 실행되는 SQL이
> 터미널에 전부 찍힙니다. 제가 SQL을 한 줄도 쓰지 않았는데 어떤 쿼리가 나가는지
> 그대로 보실 수 있습니다."

# 🟦 항목 2 — 구조

## 2-1. routers, services, repositories, models의 역할

> "네 계층으로 나눴습니다.
> **routers**는 요청에서 값을 꺼내고 화면이나 리다이렉트를 돌려줍니다. **HTTP를 아는 유일한 층**입니다.
> **services**는 업무 규칙을 판단합니다. '없는 글을 수정하려 하면 예외', 'ORM → DTO 변환' 같은 것입니다.
> **repositories**는 DB 읽기·쓰기만 합니다.
> **models**는 테이블 구조를 정의합니다.
>
> 각 계층은 **아래쪽만 압니다.** 라우터가 서비스를, 서비스가 저장소를, 저장소가 모델을 압니다.
> **반대는 없습니다.**"

**증거를 보여주세요 — 가장 강력한 설명입니다**
```bash
grep -rc "Request\|Response" services/      # 0 → 서비스는 HTTP를 모른다
grep -rc "select(\|session\|db\." routers/   # 0 → 라우터는 SQL을 모른다
```

## 2-2. 라우터와 서비스를 어떤 기준으로 분리했는가

> "기준은 **'HTTP가 사라져도 필요한 일인가'**입니다.
> 이 앱을 CLI나 REST API로 바꿔도 여전히 필요한 판단이면 **서비스에**,
> HTTP 때문에 생기는 일이면 **라우터에** 뒀습니다."

| 라우터에 있는 것 | 왜 거기 두었나 |
|---|---|
| `Form(...)`으로 폼 값 받기 | HTTP 요청 본문을 읽는 일. **서비스는 요청이 뭔지 몰라야** 함 |
| `ValidationError`를 잡아 **폼 재렌더링** | "실패하면 어떤 화면을 보여줄까"는 **화면의 문제** |
| `RedirectResponse(303)` | 리다이렉트는 **HTTP 개념** |
| `StudyLogNotFound` → **404 화면** | 서비스는 "없다"는 **업무 신호**만 주고, 404로 옮기는 건 라우터의 **번역** |

## 2-3. 모델 필드 구성과 `Session` 메서드가 대응하는 SQL ★

**필드 구성**

> "학습 기록을 남기려면 **'무엇을(title/content) 언제(studied_on) 얼마나(minutes)
> 어떤 분야에서(category)'**가 필요해서 5개로 정했습니다. 과제 권장이 3~6개였습니다.
>
> `title`, `studied_on`, `category`에 **`index=True`**를 줬습니다.
> **검색과 정렬에 쓰이는 컬럼**이기 때문입니다.
>
> `created_at`은 **`server_default=func.now()`로 DB가 채우게** 했습니다.
> 파이썬에서 시각을 넣으면 **서버 시간대에 따라 달라지지만**, DB가 넣으면 기준이 하나로 고정됩니다.
>
> `content`는 길이 제한이 없는 `Text`, 나머지는 길이를 정한 `String`입니다."

**Session 메서드 ↔ SQL 대응 — 이 표를 외우세요**

| 메서드 | 실제로 하는 일 | SQL |
|---|---|---|
| `session.add(obj)` | 세션에 **등록만** 한다. 아직 DB로 가지 않음 | (아직 없음) |
| `session.commit()` | 등록된 변경을 모아 보내고 커밋 | `INSERT`/`UPDATE`/`DELETE` + `COMMIT` |
| `session.refresh(obj)` | 방금 저장된 행을 다시 읽어 **DB가 채운 값**을 가져옴 | `SELECT ... WHERE id = ?` |
| `session.get(Model, pk)` | 기본키 조회 (세션 캐시에 있으면 쿼리 생략) | `SELECT ... WHERE id = ?` |
| `select(Model)` + `scalars()` | 2.0 스타일 조회 | `SELECT ...` |
| `session.delete(obj)` | 삭제 대상 등록 → commit 때 실제 삭제 | `DELETE FROM ... WHERE id = ?` |

**꼭 덧붙일 한 문장**

> "핵심은 **`add`가 저장이 아니라는 것**입니다. `add`는 '이 객체를 저장할 예정'이라고
> **세션에 표시만** 합니다. 실제 SQL은 `commit()` 때 한꺼번에 나갑니다.
> 그래서 **중간에 실패하면 전부 없던 일**이 됩니다."

**수정은 `add`를 다시 부르지 않는 것도 설명하세요**

> "`session.get()`으로 가져온 객체는 **이미 세션이 추적 중**입니다.
> 속성만 바꾸면 세션이 변경을 감지(**dirty checking**)해서 commit 때 `UPDATE`를 보냅니다."

# 🟦 항목 3 — 흐름 (코드를 열고 짚기)

## 3-1. 요청이 라우터 → 서비스 → 저장소 → 템플릿으로 흐르는 과정 ★

**상세 화면(`GET /logs/6`)으로 설명하세요. 코드를 순서대로 열면서:**

| 단계 | 코드 | 말할 내용 |
|---|---|---|
| ① | `main.py` `include_router` | "요청이 들어오면 FastAPI가 등록된 라우터에서 주소를 찾습니다" |
| ② | `routers/study_logs.py` `detail()` | "`/logs/{log_id}`가 맞으니 이 함수가 실행됩니다. `log_id`는 **자동으로 int로 변환**됩니다" |
| ③ | `Depends(get_db)` | "그 전에 FastAPI가 `get_db()`를 실행해 **이 요청 전용 세션**을 만들어 넣어줍니다" |
| ④ | `StudyLogService(db).get(log_id)` | "라우터는 서비스에게 시킵니다. **직접 DB를 건드리지 않습니다**" |
| ⑤ | `services` → `repo.get(log_id)` | "서비스는 저장소에게 부탁합니다" |
| ⑥ | `repositories` `db.get(StudyLog, id)` | "여기서 실제로 `SELECT ... WHERE id=?`가 나갑니다" |
| ⑦ | 서비스로 복귀 | "없으면 `StudyLogNotFound`를 던지고, 있으면 **ORM → `StudyLogRead` DTO**로 변환합니다" |
| ⑧ | `templates.TemplateResponse` | "라우터가 DTO를 템플릿에 넘기고, Jinja2가 HTML을 만들어 응답합니다" |
| ⑨ | 응답 후 | "`get_db()`의 **`finally`**가 실행되어 세션이 닫힙니다" |

**마무리 한 문장**

> "**요청 하나의 수명과 세션 하나의 수명이 정확히 같습니다.**
> 그래서 요청 중 실패하면 **그 요청에서 한 일만** 되돌아갑니다."

### ★ 꼬리 질문: "왜 `Depends`로 주입하나요?"

> "각 라우터가 직접 `SessionLocal()`을 만들면, **닫는 것을 깜빡하는 순간
> 연결이 새어나갑니다(connection leak).** 열고 닫는 책임을 한 곳에 모은 겁니다.
> 그리고 **테스트할 때 이 함수만 바꿔치기하면** 테스트용 DB로 갈아끼울 수 있습니다."

## 3-2. GET과 POST의 역할 차이

> "**GET은 조회**입니다. 같은 요청을 몇 번 보내도 서버 상태가 변하지 않습니다(**멱등**).
> 그래서 브라우저가 주소창에 남기고, 북마크·뒤로가기·새로고침·캐시가 자유롭습니다.
>
> **POST는 변경**입니다. 보낼 때마다 서버에 일이 생깁니다.
>
> 분리해야 하는 이유는 명확합니다. 만약 **삭제를 GET 링크로 만들면,
> 브라우저의 미리 읽기나 검색엔진 크롤러가 링크를 훑는 것만으로 데이터가 지워집니다.**"

## 3-3. PRG 패턴을 적용해야 하는 이유와 `RedirectResponse(status_code=303)`을 쓰는 이유 ★

### ④ 읽을 말

> "**PRG(Post-Redirect-Get) 패턴**입니다.
>
> POST를 처리한 뒤 화면을 바로 그리면, **그 화면의 주소는 여전히 POST 주소**입니다.
> 사용자가 F5를 누르면 브라우저가 '양식을 다시 제출할까요?'를 묻고,
> 확인하면 **같은 글이 또 등록됩니다.**
>
> PRG는 POST 처리 후 **리다이렉트를 돌려줘서** 주소창이 GET 주소로 바뀌게 합니다.
> 그 뒤 새로고침은 **GET이 다시 갈 뿐이라 안전합니다.**
>
> 제 코드에서는 글 등록·수정·삭제가 끝나면 전부
> `RedirectResponse(url=..., status_code=303)`을 돌려줍니다."

### ★ 왜 303인가 — **이걸 정확히 말하면 확실히 통과합니다**

> "**302 Found**는 재요청 시 **원래 메서드를 유지해도 된다**는 해석의 여지가 있어서,
> 일부 클라이언트는 **POST로 다시 보냅니다.** 그러면 PRG의 목적이 깨집니다.
>
> **303 See Other**는 규격상 **반드시 GET으로 바꿔서** 요청하라는 뜻입니다.
> 반대로 **307/308은 메서드를 유지**하라는 뜻이라 여기서는 쓰면 안 됩니다.
>
> 그래서 302도 307도 아니고 **303**입니다."

| 코드 | 의미 | PRG에 적합? |
|---|---|---|
| 301/302 | 이동됨 (메서드 유지 여부가 **모호**) | ❌ |
| **303** | **다른 자원을 GET으로 보라** | ✅ |
| 307/308 | 이동됨, **메서드 유지** | ❌ (POST가 반복됨) |

### ★ 함께 말하면 좋은 것: 삭제는 왜 링크가 아닌가

> "삭제를 GET 링크로 만들면, **브라우저의 미리 읽기나 검색엔진 크롤러가
> 링크를 훑는 것만으로 데이터가 지워집니다.**
> 그래서 제 코드에서 삭제는 링크가 아니라 **`<form method="post">`의 버튼**입니다.
> `templates/detail.html`에 있습니다."

## 3-4. ORM으로 CRUD가 동작하는 원리

**`repositories/study_log.py`를 열고 순서대로 짚으세요**

```python
def create(self, log: StudyLog) -> StudyLog:
    self.db.add(log)       # ① 세션에 등록 (아직 DB에 안 감)
    self.db.commit()       # ② INSERT 가 나가고 커밋
    self.db.refresh(log)   # ③ DB가 만든 id, created_at 을 객체에 채움
    return log
```

> "Create는 이 세 줄입니다. Read는 `session.get()`과 `select()`,
> **Update는 객체의 속성을 바꾸고 commit**하면 세션이 변경을 감지해 UPDATE를 보냅니다.
> Delete는 `session.delete()` 후 commit입니다.
>
> 제가 **SQL을 한 줄도 쓰지 않았는데 동작하는 이유**는, 모델 클래스가 테이블 구조를
> 알고 있어서 SQLAlchemy가 그걸 보고 SQL을 만들어 주기 때문입니다."

# 🟦 항목 4 — 설계와 확장 (가장 어려운 항목)

## 4-1. 폼 입력값이 `Form()`/Pydantic으로 다뤄지는 과정 ★

> "① 브라우저가 `<form method="post">`를 제출하면 입력값을
> `title=...&content=...` 형태로 인코딩해 요청 **본문**에 담아 보냅니다.
> ② FastAPI가 그 본문을 파싱합니다. 이때 **`python-multipart` 패키지가 필요**합니다.
> 이게 없으면 **서버가 시작할 때부터 오류**가 납니다.
> ③ `Form(default="")`로 선언한 매개변수에 값이 꽂힙니다. **이 시점에는 전부 문자열**입니다.
> ④ 그 문자열을 Pydantic 모델에 넣으면 `"2026-09-27"` → `date`, `"90"` → `int`로 바꾸면서
> 규칙(2글자 이상, 1~1440분, 미래 날짜 금지)까지 **한 번에 검사**합니다."

### ★ 꼬리 질문: "왜 `minutes: int = Form(...)`으로 안 받았나요?"

> "그렇게 하면 숫자가 아닐 때 FastAPI가 **422 JSON 오류**를 냅니다.
> **개발자용 응답이지 사용자 화면이 아닙니다.**
>
> 전부 문자열로 받아 Pydantic으로 직접 검증하면, 실패했을 때
> **사용자가 입력한 값이 그대로 남아 있는 폼**을 다시 보여줄 수 있습니다."

## 4-2. 레이어를 분리하지 않고 라우터에 다 넣으면 어떤 문제가 생기는가

> "**① 중복이 생깁니다.** 등록과 수정 둘 다 '제목 2글자 이상'을 검사해야 하는데,
> 라우터마다 쓰면 **한쪽만 고치는 일**이 생깁니다.
> **② 테스트가 어려워집니다.** 규칙을 확인하려면 HTTP 요청을 만들어야 합니다.
> 지금은 `StudyLogService`만 만들어서 함수 하나를 부르면 됩니다.
> **③ 바꾸기 어려워집니다.** DB를 바꾸면 **SQL이 흩어져 있는 모든 라우터**를 고쳐야 합니다.
> **④ 읽기 어려워집니다.** 한 함수 안에 HTTP 처리·검증·SQL·렌더링이 섞이면
> 어디서 뭐가 잘못됐는지 찾기 어렵습니다."

## 4-3. SQLite 대신 PostgreSQL로 바꾸려면

> "**`database.py` 한 파일입니다.**
> ① `DATABASE_URL`을 `postgresql+psycopg://user:pw@host/dbname`으로 바꾸고
> ② SQLite 전용 옵션인 `connect_args={'check_same_thread': False}`를 **제거**합니다.
> 이 옵션은 SQLite가 '연결을 만든 스레드에서만 써라'고 막기 때문에 넣은 것이라
> **다른 DB에는 필요 없습니다.**
> ③ 드라이버 패키지를 설치합니다.
>
> **모델·저장소·서비스·라우터는 한 줄도 바뀌지 않습니다.**
> ORM이 SQL 방언 차이를 흡수하기 때문입니다.
>
> 실무라면 마이그레이션 도구(**Alembic**)를 추가로 쓰겠지만,
> 이번 과제 범위에서는 `create_all`로 충분합니다."

## 4-4. 모델 간 연관관계가 필요해지면 어디를 바꿔야 하는가 ★

> "지금 `category`는 **문자열 컬럼**입니다. 이걸 별도 테이블로 분리한다면 이렇게 바꿉니다."

| 순서 | 파일 | 바꿀 내용 |
|---|---|---|
| ① | `models/category.py` (신규) | `Category` 모델 생성 (id, name) |
| ② | `models/study_log.py` | `category: str` → `category_id: Mapped[int] = mapped_column(ForeignKey("categories.id"))` + `relationship()` |
| ③ | `repositories/study_log.py` | 목록 조회에 `join` 또는 **`selectinload`** 추가 (N+1 방지) |
| ④ | `schemas/study_log.py` | `category: str` → 중첩 스키마 `category: CategoryRead` |
| ⑤ | `templates/form.html` | 분야 select의 선택지를 **DB에서 읽어온 목록**으로 |
| ⑥ | DB | 기존 데이터 이전(마이그레이션) 필요 |

> "**라우터와 서비스의 구조는 거의 그대로입니다.** 서비스가 돌려주는 DTO 모양만 유지하면
> 화면 코드도 필드 이름 정도만 바뀝니다. **계층을 나눠둔 효과가 여기서 드러납니다.**
>
> 그리고 **N+1 문제**를 미리 말씀드리면 — 목록 100건을 그리면서 카테고리를 각각 조회하면
> **쿼리가 101번** 나갑니다. `selectinload`로 한 번에 가져와야 합니다."

## 4-5. REST API + 프론트엔드 분리로 전환하면 어떤 레이어가 바뀌는가 ★

| 레이어 | 전환 시 | 이유 |
|---|---|---|
| `models/` | **그대로** | 데이터 구조는 화면과 무관 |
| `repositories/` | **그대로** | DB 접근은 화면과 무관 |
| `services/` | **그대로** | 업무 규칙은 화면과 무관 |
| `schemas/` | **거의 그대로** (응답 스키마로 재사용) | 이미 DTO로 분리해 둠 |
| `routers/` | **바뀜** | `TemplateResponse` → JSON, `RedirectResponse` → `201 Created` + 본문 |
| `templates/`, `static/` | **삭제** | 프론트엔드 프로젝트로 이동 |

> "**서버의 3분의 2는 그대로 쓰고 라우터만 새로 씁니다.**
> 그게 계층을 나눈 가장 큰 이유입니다.
>
> 구체적으로는 **PRG도 없어집니다.** REST API에서는 POST 응답으로
> **201 Created + 생성된 자원**을 주고, 새로고침 문제는 브라우저가 아니라
> 프론트엔드 코드가 처리합니다.
>
> 폼 처리도 `Form()` 대신 **Pydantic 모델을 요청 본문(JSON)으로** 받게 바뀝니다.
> 그리고 **CORS 설정이 새로 필요**해집니다. 프론트가 다른 주소에서 뜨니까요."

# 🟦 "경험 정도 (재구현 가능 여부)"

평가표 마지막에 평가자가 체크하는 칸입니다. **겪은 문제**를 말하는 게 가장 효과적입니다.

**① 라우트 순서 때문에 `/logs/new`가 안 열리던 문제**
> 처음에 `/logs/{log_id}`를 먼저 선언했더니 `/logs/new`가 422 오류를 냈습니다.
> FastAPI가 **선언 순서대로** 주소를 맞춰보기 때문에, `new`를 정수 id로 해석하려 한 겁니다.
> **구체적인 경로를 변수 경로보다 먼저** 선언해서 해결했고, 주석으로 남겨뒀습니다.

**② curl 테스트에서 한글이 깨지던 문제**
> curl로 `-d "title=제목"`을 보냈더니 DB에 깨져 들어갔습니다. 처음엔 앱 버그인 줄 알았는데,
> **curl이 값을 퍼센트 인코딩하지 않고 raw 바이트로 보낸 것**이 원인이었습니다.
> **브라우저는 항상 인코딩해서 보내므로 실제 사용에는 문제가 없었고**,
> `--data-urlencode`로 보내니 정상이었습니다. README에 주의사항을 적어뒀습니다.

**③ 순환 참조를 피하려고 파일을 나눈 것**
> Jinja2 설정을 `main.py`에 뒀더니, `main`이 `routers`를 import하고
> `routers`가 다시 `main`을 import하는 **순환 참조**가 생겼습니다.
> **양쪽이 모두 쓰는 것은 제3의 파일**(`templating.py`)에 두는 것이 정석이라 그렇게 분리했습니다.

**④ 일부러 하지 않은 것 — 트레이드오프를 아는 사람으로 보입니다**
> `create_all()`로 테이블을 만드는 건 **컬럼이 바뀌면 반영되지 않습니다.**
> 실무라면 Alembic 마이그레이션을 써야 하지만, 이번 과제는 단일 모델이고
> 스키마가 고정이라 **복잡도를 늘리지 않는 쪽을 택했습니다.**
